# Q: НІЧОГО НЕ ЗМІНИЛОСЯ НА IOS ДОСІ НЕ ВІДКРИВАЮТЬСЯ ФОТО ПРОСТО ЧОРНИЙ ЕКРАН

## Answer

Expanded from graph vocabulary: [attachment, image, preview, ios, webp, uri, compression, mime, resolve, storage, local, staged]. The previous Modal, Reanimated, FlatList, GestureDetector, and ScrollView hypotheses were disproven by device retests. The attachment pipeline generates full uploads as photo-*.webp while its visible LQIP thumbnail is a separate data:image/jpeg. The full image was rendered with React Native Image, whereas expo-image explicitly supports WebP on iOS. The corrected implementation renders iOS attachment images with expo-image and forces useAppleWebpCodec={false}, selecting the standard libwebp decoder; Android and web keep their existing renderer.

## Outcome

- Signal: corrected
- Correction: The black screen was a decoder/format mismatch: full attachments are generated WebP but thumbnails are JPEG LQIP. Use expo-image with the standard libwebp codec on iOS; UI-layer rearrangements do not address it.
