<section id="in-app">
  <h2>1. Delete an account in the app</h2>
  <ol className="steps">
    <li>Open PlanIt while signed in to the account you want to delete.</li>
    <li>Open <strong>Settings</strong>.</li>
    <li>Select <strong>Account Settings</strong>.</li>
    <li>Select <strong>Delete Account</strong>.</li>
    <li>Verify with your linked password, Google account, or Apple account.</li>
    <li>Review the final warning and confirm permanent deletion.</li>
  </ol>
  <p>The app uses recent Firebase reauthentication to protect against unauthorized deletion. A successful
    verification remains usable for five minutes. Google and Apple verification opens the applicable provider
    flow; PlanIt does not ask you to create a separate password for a social-sign-in account. If Apple is linked,
    PlanIt requires the Apple flow even when another provider is also linked, because a new Apple token or
    authorization code is required for revocation.</p>

  <div className="notice">
    <strong>How the current in-app flow works</strong>
    <p>After verification, PlanIt creates a minimal irreversible deletion marker to block new writes from other
      signed-in devices. It then deletes known Firestore account subcollections, legacy schedule data, stored
      notifications and devices, every shared-schedule record owned by the account, and all objects below the
      account's Firebase Storage attachment path. The Firebase Authentication account is deleted only after
      those cloud steps succeed. A failed step is reported and the sign-in record is kept so cleanup can be
      retried instead of being reported as a false success.</p>
    <p>On the current device, PlanIt also attempts to clear the signed-in schedule cache, attachment cache,
      scheduled notifications, and widget schedule snapshot. This does not erase Guest Mode content,
      downloaded/exported files, another device's local storage, or recipient-controlled copies.</p>
  </div>

  <div className="warning">
    <strong>Sign in with Apple authorization</strong>
    <p>On web, PlanIt asks Firebase to revoke the Apple access token obtained during reauthentication before
      deletion starts. Native iOS returns an authorization code whose secure exchange requires a trusted
      server-side Apple credential. PlanIt sends that code to its configured secure revocation endpoint and
      does not begin deleting PlanIt data unless revocation is confirmed. If revocation cannot be confirmed,
      retry or contact support. You may separately remove PlanIt from your Apple ID sign-in settings, but that
      action alone does not delete the PlanIt account. Do not send an authorization code or token by email.</p>
  </div>
</section>

<section id="verification">
  <h2>3. Verification and timing</h2>
  <p>Verification protects your account from malicious deletion requests. We normally verify control of the
    linked email address and may ask for limited account information that only the account holder is likely to
    know. We use verification information only to process and document the request.</p>
  <p>We will acknowledge a valid request and aim to complete it without undue delay, generally within 30 days.
    Where the GDPR applies, we respond within one month unless a permitted extension is necessary because of
    complexity or the number of requests; if so, we will notify you within the initial month and explain the
    extension. Other laws may require a different period.</p>
  <p>If we cannot verify the request or must retain limited data, we will explain the reason and available
    complaint options where required by law.</p>
</section>

<section id="scope">
  <h2>4. What deletion covers</h2>
  <p>Subject to successful verification and applicable legal exceptions, a comprehensive request is intended to
    cover:</p>
  <ul>
    <li>the Firebase Authentication account, email, display name, and provider links;</li>
    <li>cloud schedules, tasks embedded in schedule data, settings, themes, reminders, and synchronization
      records stored in PlanIt's Firestore account paths;</li>
    <li>registered-device records, public-IP login history, push tokens, and stored account notifications;</li>
    <li>cloud attachments and related Firebase Storage metadata that can be located under the account; and</li>
    <li>active, expired, or stored shared-schedule records that can be located by owner ID or supplied share
      code.</li>
  </ul>
  <p>PlanIt retains an irreversible deletion-prevention marker containing the Firebase user ID and request
    timestamp, but no email address, schedule, attachment, or profile content. This narrow record prevents old
    authenticated sessions from recreating data after deletion and documents the security state of the
    deleted identifier.</p>
  <p>We may retain the minimum information needed to comply with law, resolve or defend legal claims, prevent
    fraud or repeated abuse, and document that a rights request was completed. Such retained data will not be
    used to continue the deleted account.</p>
</section>

<section id="not-remote">
  <h2>5. What cannot be erased remotely</h2>
  <ul>
    <li><strong>Local data outside the current cleanup:</strong> Guest Mode schedules, downloaded files,
      operating-system or browser backups, provider-managed authentication storage, and data on another
      device/browser.</li>
    <li><strong>Recipient-controlled copies:</strong> schedules another person imported, copied, screenshotted,
      downloaded, or received through a share code or system share sheet.</li>
    <li><strong>Downloaded/exported files:</strong> copies in device downloads, photo libraries, document
      folders, backups, cloud drives, email, or other apps.</li>
    <li><strong>Provider residuals:</strong> encrypted backups, immutable security logs, fraud-prevention
      records, and provider-controlled analytics or diagnostics until their retention cycles expire.</li>
    <li><strong>De-identified or aggregated statistics:</strong> information that can no longer reasonably be
      linked to you may be retained.</li>
  </ul>
  <p>Firebase states that Crashlytics crash traces and associated identifiers are retained for 90 days before
    removal begins. Google Analytics user/event-level retention follows the configured property setting, while
    aggregated reports may remain longer. Account deletion does not automatically identify every Analytics
    installation record unless the necessary app-instance identifier is available.</p>
</section>

<section id="local-data">
  <h2>6. Clear local or Guest Mode data</h2>
  <h3>Android or iOS</h3>
  <ol>
    <li>Delete any files you downloaded or exported from PlanIt.</li>
    <li>Use PlanIt's reset/cleanup controls where available.</li>
    <li>In the device's application settings, clear PlanIt storage/data if the platform offers that option.</li>
    <li>Uninstall PlanIt from every device. Review device or cloud backups if you need those copies removed too.</li>
  </ol>

  <h3>Web</h3>
  <ol>
    <li>Sign out and close all PlanIt tabs.</li>
    <li>Use the browser's site-data controls to clear storage for the PlanIt web origin, including local storage,
      IndexedDB, cache, and cookies/storage created by providers.</li>
    <li>Review the <a href="./cookies">Cookie &amp; Similar Technologies Policy</a> and use PlanIt's
      Cookie settings control if you only want to change optional web Analytics consent.</li>
    <li>Delete downloaded or exported files separately.</li>
  </ol>

  <h3>Guest Mode</h3>
  <p>Guest Mode does not create a PlanIt cloud account, so support cannot remotely identify or erase the guest
    schedule stored on your device. Clearing app/browser data and uninstalling are the deletion method for that
    content. Technical data already held by advertising, analytics, crash, hosting, update, or network
    providers follows the rules described in the <a href="./privacy">Privacy Policy</a>.</p>
</section>

<section id="after">
  <h2>7. After deletion</h2>
  <p>The deleted account cannot be restored. You may later create a new account with the same email if Firebase
    and the sign-in provider permit it, but the new account will have a different user identity and deleted data
    will not automatically return. A recipient's imported schedule remains in that recipient's account unless
    they delete it.</p>
</section>
